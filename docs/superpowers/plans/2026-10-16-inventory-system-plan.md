# 轻量级进销存系统 — 实施计划（Implementation Plan）

- 日期：2026-10-16
- 依据：[总体设计文档](../specs/2026-10-16-inventory-system-design.md)（已确认 6 项决策）
- 交付原则：分模块交付，每模块交付 = 可运行功能 + 操作说明 + 「常见问题 / 数据出错如何回滚」

---

## 0. 技术选型（锁定）

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面端壳 | Electron（electron-builder `portable` 目标） | 免安装 `.exe`，支持开机自启 |
| 桌面端 UI | Vue3 + Vite + TypeScript + Pinia + Element Plus | 表格优先；深浅色主题走 CSS 变量 |
| 桌面端本地库 | better-sqlite3（同步 API，事务简单） | 离线主库；WAL 模式 |
| 局域网服务 | Node `http` + `ws`（端口 8765，可配） | 主节点提供 `/sync/push`、`/sync/pull`、`/health` |
| 小程序 | 原生微信小程序 + TDesign 小程序组件 | 4 个 Tab，不做后台管理 |
| 云端 | 微信云开发 CloudBase（云函数 + 云数据库） | 权威 `change_log` 汇总 + 小程序 API |
| 公共代码 | `packages/shared`（TS）：实体定义、ULID、HLC、同步 apply 规则 | 桌面端与云函数共用同步逻辑 |

工程结构：

```
/workspace
├─ apps/
│  ├─ desktop/          # Electron + Vue3 + SQLite
│  ├─ miniprogram/      # 原生微信小程序
│  └─ cloud/            # CloudBase 云函数
├─ packages/shared/     # 实体模型 / ULID / HLC / 同步 apply / 校验规则
├─ docs/
│  ├─ specs/            # 设计文档
│  ├─ plans/            # 本文件
│  └─ modules/          # 每模块的操作说明 + 常见问题/回滚说明
└─ package.json         # pnpm workspace
```

## 1. 阶段总览

| 阶段 | 内容 | 依赖 | 产出 |
|---|---|---|---|
| P0 | 脚手架与骨架 | — | 可启动的空壳桌面端 + 建表脚本 + shared 包 |

## 2. P0 脚手架与骨架

**任务**

1. 初始化 pnpm workspace 与 `packages/shared`（TS 编译产物：ULID 生成、HLC 生成/比较、实体 Zod schema、`applyChange()` 同步应用规则）。
2. 建库脚本 `apps/desktop/src/main/db/schema.sql`：按设计文档 §5 生成全部表（实际共 41 张）+ 索引 + `PRAGMA journal_mode=WAL`、`foreign_keys=ON`；写入 `schema_version` 用于后续迁移。
3. 数据访问层：`db.ts`（连接单例）+ `repository.ts`（统一 `insert/update/softDelete`，**自动补同步字段并追加 `_change_log`**，全部包在一个事务里）。
4. Electron 主进程 / preload / 渲染进程三段式骨架，IPC 通道约定（`db:query`、`db:mutate`、`dialog:excel`）。
5. Vue3 骨架：左侧菜单 + 表格工作区布局、路由表（按 §6.1 页面结构）、主题切换（深/浅 CSS 变量）、Pinia store（当前用户、配置）。
6. 首批种子数据：`sys_config`（`allow_negative_stock=0`、`backup_keep=7`、`lan_port=8765`）、默认单位（个/件/箱/kg）、默认管理员角色。

**验收**：能起桌面端；能建库并看到 41 张表；插入一条主数据后 `_change_log` 同步出现一条日志；主题可切换。

## 3. P1 主数据

**状态**：✅ 已完成（2026-10-16）。桌面端「基础资料」10 个页面 + Excel 模板中心可用；`pnpm -r typecheck` 通过；`pnpm -r test` 40 项全通过（桌面端 24 + shared 16）。

**任务**

1. 商品管理：列表（按 名称/编号/条码/类别 搜索）、详情、新增编辑、停用、库存预览（只读，库存表在 P3 才有数据）。
2. 多计量单位：`product_unit` 维护（基本单位 + 换算率 + 单位条码 + 按单位定价）；录入单据时按单位选择并自动折算 `base_qty`。
3. 商品类别：多级树（`path` 物化路径）。
4. 计量单位、仓库、货位（按仓库的树/列表）、客户、供应商、部门 CRUD。
5. 编码规则：类别码 + 流水号，自动生成商品编号 / 单据号。
6. 期初建账：录入 `init_qty / init_cost`（仅主数据侧；P3 生成期初流水）。
7. Excel 模板中心 + 导入导出：模板下载（商品档案/客户/供应商/期初库存/采购入库/销售出库）、字段自动映射、**逐行报错并标出错误行**、修正后重导。

**验收**：商品可增改停用与搜索；一商品可配多单位并正确折算；导入 100 行中若第 7、31 行编号重复，仅这两行报错且其余成功；导出 `.xlsx`。

**交付文档**：`docs/modules/P1-主数据.md`。

## 4. P2 出入库

**状态**：✅ 已完成（2026-10-16）。桌面端「采购（入库）」「销售（出库）」7 个单据页面 + 通用单据引擎（草稿/审核/取消审核/红冲/转单）可用；`pnpm -r typecheck` 通过；`pnpm --filter @inventory/desktop test` 42 项全通过（含本阶段 14 项单据场景）。

**任务**

1. 单据通用能力：单据编号、明细表格（扫码枪加行、多单位）、合计、保存草稿、**提交审核**、审核后生效、**取消审核**（回待审核后可继续修改；生成反向冲销流水 + 作废对应应收/应付，附前置校验）、红冲（生成 `reversal_of` 反向单据）。
2. 采购链路：采购订单 →（转）采购入库单 → 审核 → 写 `stock_ledger` 入库流水 + 生成 `ap_bill` 应付。
3. 销售链路：销售订单 →（转）销售出库单 → 审核 → 写 `stock_ledger` 出库流水（快照 `cost_price/cost_amount`）+ 生成 `ar_bill` 应收。
4. 入库类型：采购入库 / **部门领用**（领用部门、领用人、用途）/ **生产入库**（成品，无 BOM）。领用出库同样写流水。
5. 退货：退货入库（针对采购）、退货出库（针对销售），红字冲销。
6. 审核校验：`allow_negative_stock=0` 时，出库审核校验可用量，不足则**不允许审核通过**并提示具体商品/仓库。

**验收**：单据只能审核后影响库存与账；**取消审核**后库存与应收应付正确回退、单据回到待审核可编辑；红冲行为正确；负库存开关两种状态行为符合预期；前置校验（已核销 / 已被下游引用 / 已红冲）能正确阻止取消审核。

**交付文档**：`docs/modules/P2-出入库.md`（含红冲回滚说明）。

## 5. P3 库存

**状态**：✅ 已完成（2026-10-16）。桌面端「库存」5 个页面（实时库存查询 / 库存流水 / 库存预警 / 库存调拨 / 库存盘点）+ 库存重算引擎（幂等、按维度增量重算）+ 库存单据引擎（调拨 / 盘点）可用；P2 单据审核 / 取消审核 / 红冲已挂接重算钩子；`pnpm -r typecheck` 通过；`pnpm --filter @inventory/desktop test` 54 项全通过（含本阶段 12 项库存场景）；`pnpm build` 通过。

**任务**

1. 库存重算引擎：`recomputeBalance(productId?, warehouseId?)` —— 由 `stock_ledger` 按时间序重放，计算 `qty / locked_qty / avail_qty / cost_amount / avg_cost`（**移动加权平均**），写入 `stock_balance`。审核、红冲、同步 apply 后触发增量重算。
2. 实时库存查询：按 商品/仓库/货位 筛选，显示数量、成本金额、可用量。
3. 库存流水：只读列表，支持按单据追溯；红冲入口。
4. 库存预警：`min_stock / max_stock` 阈值标色。
5. 库存调拨（仓库间）与库存盘点（生成盈亏流水）。

**验收**：连续「入库 10 @3 → 入库 10 @5 → 出库 4」后 `avg_cost` 与 `cost_amount` 正确；断网重算与联网后结果一致（幂等）。

**交付文档**：`docs/modules/P3-库存.md`。

## 6. P4 财务

**状态**：✅ 已完成（2026-10-16）。桌面端「财务」3 个页面（应收管理 / 应付管理 / 资金账户流水）+ 收付款单引擎（`ar_receipt` / `ap_payment`：保存 / 审核 / 取消审核 / 红冲 + 核销明细服务端权威重建）+ 往来单已收/已付与资金账户余额派生重算可用；`pnpm -r typecheck` 通过；`pnpm --filter @inventory/desktop test` 64 项全通过（含本阶段 10 项财务场景）；`pnpm build` 通过。

**任务**

1. 应收：出库审核生成 `ar_bill`；收款单 `ar_receipt` + 核销明细 `ar_receipt_apply`；支持部分收款、账期与欠款余额。
2. 应付：入库审核生成 `ap_bill`；付款单 `ap_payment` + 核销 `ap_payment_apply`。
3. 资金账户：现金/银行/微信/支付宝，收付款落账户流水。
4. 单据审核后生效；收付款单同样需审核。

**验收**：部分收款/部分付款后余额与核销状态正确；一笔收款可核销多张应收单。

**交付文档**：`docs/modules/P4-财务.md`。

## 7. P5 报表

**任务**：6 张报表全部支持 日期 / 仓库 / 客户或供应商 / 商品 筛选 + 导出 Excel。

1. 进销存明细表（每笔流水）
2. 进销存汇总表（期初 + 本期入 − 本期出 = 期末，按商品/按仓库）
3. 收货对账单（供应商 + 时间：入库数量/金额、已付/未付）
4. 发货对账单（客户 + 时间：出库数量/金额、已收/未收）
5. 发货成本表（每张销售单的成本金额）
6. 销售毛利表（销售额 − 成本额 = 毛利 / 毛利率，按商品/客户/时间/业务员）

**验收**：汇总表能与明细表勾稽一致（期初+入−出=期末）；导出的 Excel 数值与页面一致。

**交付文档**：`docs/modules/P5-报表.md`。

## 8. P6 小程序

**任务**

1. 原生小程序工程 + TDesign 小程序组件；微信登录（`openid` → 绑定 `app_user` 或角色）。
2. Tab1 工作台（库存预警摘要、扫一扫入口、我的应收）、Tab2 查库存（搜索/扫码 → 商品库存详情）、Tab3 开单（销售出库单：选客户 → 扫码/搜索加商品 → 数量/售价 → 提交）、Tab4 我的（我的应收、我的单据、同步状态、切换账号）。

**交付文档**：`docs/modules/P6-小程序.md`。

## 9. P7 同步联调

**任务**

1. 主节点 LAN 服务（`/health`、`/sync/push`、`/sync/pull` + WebSocket 通知 + mDNS 发现）；桌面端「主节点 IP」配置与自动发现。
2. 同步引擎：`_change_log` 推拉、`(device_id, seq)` 幂等去重、`_sync_cursor` 断点续传、后台定时 + 网络恢复触发。
3. `applyChange()`：单据/流水 append-only 直接插入；主数据行级 HLC LWW + `dirty_fields` 字段级合并；冲突写 `_conflict` 并置 `sync_state=2`。
4. CloudBase 侧：`change_log` 集合 + 云函数 `syncPush/syncPull`（复用 `packages/shared` 的 apply 规则）。
5. 「同步中心」界面：同步状态、待同步条数、冲突列表与人工裁决、手动同步。
6. 联调用例：两台桌面端并发开单、同商品改售价、一端审核一端红冲、小程序离线开单后补传、主节点短暂离线恢复。

**验收**：断网期间两台桌面端各开单，恢复后两端库存一致且不丢单；同字段冲突能在冲突中心看到并可回滚；小程序离线单据补传成功。

**交付文档**：`docs/modules/P7-同步与冲突.md`。
