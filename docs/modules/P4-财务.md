## 2. 财务口径（关键概念）

本阶段的账务体系把「事实」与「派生状态」严格分开：

| 表 | 角色 | 可变性 | 谁能写 |
|---|---|---|---|
| `ar_bill` / `ap_bill` | **应收 / 应付单**（由出库 / 入库单据审核派生的事实） | 只读 | P2 单据审核 / 取消审核 / 红冲时写入 |
| `ar_receipt` / `ap_payment` | **收款单 / 付款单**（账务事实） | 追加式（红冲生成反向单，不删原单） | 收付款单引擎 |
| `ar_receipt_apply` / `ap_payment_apply` | **核销明细**（哪笔收款冲抵哪张往来单） | 随收付款单草稿保存重建 | 收付款单引擎 |
| `ar_bill.received_amount` / `ap_bill.paid_amount` | **派生计数**（已收 / 已付） | 由核销明细重算 | 重算引擎（原始 SQL，不经 Repository） |
| `account.balance` | **派生计数**（账户余额） | 由已审核收付款单重算 | 重算引擎（原始 SQL，不经 Repository） |

由此得出两条不变式：

1. **往来单结清状态由金额派生**：`remaining = amount − 已收/已付`，据此判定 `未结清 / 部分结清 / 已结清`，不单独存状态字段。
2. **任何回退都是「再写一条反向单」**：红冲生成反向**已审核**单据 R（金额与核销全部取负），原单置「已红冲」，二者净额为 0；绝不删除历史。

## 3. 收付款单引擎

收付款单复用与 P2 / P3 **完全一致**的单据状态机与交互。

### 3.1 状态机

| 状态值 | 含义 | 可执行操作 |
|---|---|---|
| 0 | 待审核（草稿） | 编辑、审核 |
| 1 | 已审核（生效） | 查看 / 取消审核 / 红冲 |
| 9 | 已红冲 | 仅查看，不可再操作 |

**只有 `status = 1`（已审核）才让核销生效、才影响账户余额。**

### 3.2 计入口径

核销与余额的计入条件统一为收付款单 `status ≠ 0`（即已审核 1 或已红冲 9）：

- 草稿（0）**不计入**；
- 「取消审核」把状态改回 0，该单核销**自动失效**；
- 「红冲」保留原单（9，正额）并追加反向单（1，负额），**净额为 0**。

因此余额只由核销明细与收付款单状态决定，**天然幂等**：无论重算多少次，结果都收敛一致。

### 3.3 服务端权威重建核销明细

保存收付款单（新建 / 修改草稿）时，服务端**先软删旧核销明细、再写入本次明细**，以服务端校验为准，不信任前端提交：

- 往来单位（客户 / 供应商）必填；
- 单据金额必须 > 0；
- 每笔核销必须对应**存在且属于该往来单位**的往来单；
- 核销金额合计不得超过单据金额。

审核时再做一次**未结清余额前置校验**：任一笔核销金额超出该往来单当前未结清余额即拒绝，防止超额核销。

### 3.4 触发重算的时机

- **审核**：核销生效 → 重算受影响往来单的已收 / 已付 → 重算该资金账户余额；
- **取消审核**：核销失效 → 同样重算；
- **红冲**：原单 + 反向单一起参与重算。

## 4. 操作说明

### 4.1 推荐使用顺序

1. P1 建好 客户 / 供应商 主数据；本阶段还需在数据库中有资金账户（现金 / 银行 / 微信 / 支付宝）。
2. P2 完成销售出库（生成应收单）或采购入库（生成应付单）。
3. P4 在「应收管理 / 应付管理」里对客户收款、对供应商付款，并核销对应往来单。
4. 用「资金账户流水」核对收支与余额。

### 4.2 应收管理 / 应付管理

页面分两块：

**上：往来单（只读）** —— 应收单在「应收管理」、应付单在「应付管理」。

- 列：来源单号、往来单位、单据金额、已收/已付、未结清（红色表示仍有欠款）、结清状态、单据日期、到期日。
- 可按 **结清状态**（未结清 / 部分结清 / 已结清）过滤；应收单由销售出库审核自动生成，不在此处手工新增。

**下：收款单 / 付款单**

- 「新增收款单 / 新增付款单」→ 结算弹窗：
  1. 选 **客户 / 供应商**（必填）；
  2. 选 **资金账户**（可选）与 **结算方式**（现金 / 银行转账 / 微信 / 支付宝 / 其他）；
  3. 填 **单据金额** 与 **收款 / 付款日期**；
  4. 明细区自动列出**该往来单位下全部未结清**的往来单，可逐行填写**本次核销金额**，或点「按金额自动核销」从最早未结清单据开始按金额顺序冲抵，点「清空」重新填。
  - 顶部实时显示「已核销合计 / 单据金额 / 未核销」。
- 保存后为**草稿（待审核）**，此时不影响任何余额；点「审核」才生效。
- 已审核单据可 **取消审核**（核销失效、余额回退，回到待审核可编辑）或 **红冲**（生成反向单，原单置已红冲、净额归零）。

> 一笔收款 / 付款**可同时核销多张**往来单；多笔收款也可**部分**核销同一张往来单。

### 4.3 资金账户流水

- **账户余额一览**：每个资金账户名称 + 余额，底部合计；点「全量重算」按「已审核收款单 − 已审核付款单」重建全部余额（对账兜底）。
- **流水列表**：由已审核（`status ≠ 0`）的收付款单合并派生，**不单独建流水表**。
  - 列：业务日期、资金账户、方向（收入 / 支出）、单据编号、往来单位、金额、状态；
  - 可按 **资金账户 / 方向 / 日期区间** 过滤；
  - 红冲后原单与反向单都会出现在流水中（一正一负，净额为 0）。

## 5. 常见问题

**Q：为什么往来单不能手工新增？**
应收 / 应付单是由出库 / 入库单据审核**派生的事实**，其来源、金额、客户/供应商都由源单决定，因此只读。要对账请开收 / 付款单核销。

**Q：草稿收付款单会影响余额吗？**
不会。只有审核（`status = 1`）后核销才生效、账户余额才变动。

**Q：取消审核和红冲有什么区别？**
- 取消审核：把已审核单据退回草稿（状态回 0），核销与余额回退，单据可继续编辑后重新审核。
- 红冲：不修改已生效的历史，而是**追加一张反向已审核单据**冲平，原单标记为已红冲；原单不可再操作。两者净额结果都回到 0。

**Q：账户余额对不上怎么办？**
点「资金账户流水」页的「全量重算」。余额完全由已审核收付款单决定，重算是幂等的，多次点击结果一致。

**Q：同一张应收单能被多笔收款核销吗？**
可以。多笔收款分别核销同一张应收单，`已收` 累加；当 `已收 ≥ 单据金额` 时结清状态变为「已结清」，该单不再出现在未结清列表中。
