## 1. 拓扑与角色

星型拓扑，一台电脑作为**主节点**（权威中继），其他电脑作为**客户端**：

```
        客户端A ──push──▶ ┌─────────┐ ◀──push── 客户端B
                         │ 主节点   │
        客户端A ◀─pull─── │(LAN服务) │ ───pull──▶ 客户端B
                         └─────────┘
```

| 角色 | 含义 | 需要做什么 |
|---|---|---|
| `standalone` | 单机（默认） | 不参与同步，数据仅本机 |
| `master` | 主节点 | 在「同步中心」点「启动主节点服务」；其他电脑填本机地址 |
| `client` | 客户端 | 填写主节点地址；点「立即同步」或启动后台同步 |

主节点无需特殊数据，也无需单独部署程序——它就是一端启用了 LAN 服务的桌面端。

---

## 2. 同步数据流

每一步都建立在 P0 起就有的 **业务表 + `_change_log` 同事务** 基础上：

1. **本端写入**：任何业务写（新增/修改/删除）都会在 `_change_log` 追加一条 `pushed = 0` 的变更（`log_id` 为 ULID，`seq` 本端自增）。
2. **推送（客户端 → 主节点）**：`collectOutbox()` 取 `pushed = 0` 的变更，POST 给主节点；成功后 `markPushed()` 置 `pushed = 1`。
3. **主节点接收**：按 `(device_id, seq)` 用 `_sync_cursor.last_push_seq` **幂等去重** → `applyIncoming()` 落库 → 以**新的全局 `seq`** 写入主节点 `_change_log`（中继，`pushed = 1`）→ `ackSeq` 返回给客户端。
4. **拉取（客户端 ← 主节点）**：客户端按 `_sync_cursor.last_pull_seq` 拉取 `seq > 游标` 的增量 → `applyIncoming()` 落库 → 推进游标（**断点续传**）。
5. **回声抑制**：`applyIncoming()` 会跳过 `device_id == 本机` 的变更，避免把自己推出去的变更再应用一遍。

**去重与收敛的保证**：
- 主节点：`(device_id, seq)` 幂等 + `log_id` 唯一（重复推送不产生新中继记录）。
- 客户端：全局 `seq` 游标只前进；`applyChange()` 对 append-only「已存在即 noop」、对主数据「HLC 不新即 noop」，因此**重复应用天然幂等**。

## 3. 同步规则（复用 `packages/shared` 的 `applyChange`）

| 实体类型 | 例子 | 规则 |
|---|---|---|
| append-only | `stock_ledger`、各类单据与明细 | 只 insert，永不 LWW；本地已存在则 noop |
| 主数据 | `product / customer / unit / warehouse / app_user / role …` | 行级 **HLC LWW** + `dirty_fields` **字段级合并**；同字段真冲突 → 落 `_conflict` 并置 `sync_state = 2` |
| 派生状态 | `stock_balance / ar_bill / ap_bill` | **不参与 apply**，各端本地重算（`recomputeBalance` 幂等） |

字段级合并示例：A 改「名称」、B 改「售价」——两个字段各自保留，**不冲突**；A、B 同时改「名称」且值不同——记一条冲突，按 HLC 晚者胜，并在冲突中心待人工裁决。

## 4. 主节点 LAN 接口

默认端口 `8765`（`sys_config.lan_port`，可在同步中心修改）。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/health` | 健康检查：`{ deviceId, pendingCount, conflictCount, seq, time }` |
| `POST` | `/sync/push` | 入参 `{ deviceId, changes:[…] }`；返回 `{ ackSeq, applied, conflicts, duplicate }` |
| `GET` | `/sync/pull?since=<seq>` | 返回 `{ changes:[…], nextSeq }`（`seq > since`） |
| `GET` | `/events` | **SSE 通知**：有新变更时推送 `event: change`，客户端据此触发拉取 |

变更结构（`change`）：`{ logId, seq, deviceId, entity, entityId, op, payload, hlc, createdAt }`。

## 5. 同步中心操作步骤

菜单：**系统 → 同步中心**。

**主节点（电脑一）**
1. 节点角色选「主节点」→ 填 LAN 端口（默认 8765）→ 保存配置。
2. 点「启动主节点服务」，看到「运行中 http://…」即成功；把该地址（含本机局域网 IP）告诉其他电脑。

**客户端（电脑二）**
3. 节点角色选「客户端」→ 填主节点地址（如 `http://192.168.1.10:8765`）→ 保存配置。
4. 点「立即同步」，或点「启动后台同步」（按间隔自动轮询）。
5. 顶部卡片可查看 **待同步条数 / 待处理冲突 / 上次同步时间**。

**冲突处理**
6. 底部「冲突中心」列出待处理冲突：显示 实体 / 字段 / 本地值 A / 远端值 B / 自动裁决。
7. 点「采用本地」或「采用远端」→ 二次确认 → 裁决值写回实体（会作为本端变更继续同步出去），冲突状态置「已裁决」。

## 6. 两机联调验收（对应计划 §9 验收）

1. **两端一致 / 不丢单**：A 与 B 各开若干单据（或改主数据），B 点「立即同步」推送；A 点「立即同步」拉取 → A、B 的库存与单据一致，且两边条数相同。
2. **同字段冲突可见**：A、B 同时改同一商品的「售价」→ 先同步的一端先落库，后同步的一端在「冲突中心」看到该字段冲突，可一键裁决。
3. **断网恢复**：断开 B 的网络，B 继续开单（`_change_log` 累积 `pushed = 0`）；恢复网络后 B 点「立即同步」，待同步条数归零，A 侧补齐。
4. **重复推送幂等**：对同一批变更重复点「立即同步」，「待同步条数」不再增加（`duplicate` 生效）。

> 自动化覆盖：`apps/desktop/test/sync-core.test.ts`、`lan.test.ts`、`sync.test.ts` 已覆盖上述场景（含通过回环地址真实起 LAN 服务 + `fetch` 联调 + SSE 通知）。

## 7. 常见问题 / 数据出错如何回滚

| 现象 | 原因 / 处理 |
|---|---|
| 点「立即同步」提示「未配置主节点地址」 | 客户端角色必须填主节点地址；主节点角色无需填。 |
| 客户端连不上主节点 | 确认主节点服务「运行中」；确认两机同一局域网、地址为本机**局域网 IP**（非 127.0.0.1）；确认防火墙放行端口。 |
| 「待同步条数」不降 | 主节点不可达时不会置 `pushed = 1`，变更会保留并在恢复后重推（不丢单）。 |
| 冲突中心为空但两端值不同 | 若两边改的是**不同字段**，会字段级合并、不产生冲突；只有**同字段不同值**才记冲突。 |
| 想撤销一次裁决 | 冲突已置「已裁决」不再回到待处理；直接在该实体对应页面把该字段改回目标值即可（会作为新变更同步）。 |
| 派生数据（库存余额）两端不一致 | 进入「实时库存查询」触发**重算**（`recomputeBalance` 幂等），由流水重放得到一致结果；派生表不参与同步。 |
| 误同步了大量数据想回退 | 同步只影响 `_change_log` / 业务表；可用「数据备份恢复」（P0 基础）恢复到快照。同步动作本身不改结构、不改系统表。 |
