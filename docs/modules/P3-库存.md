## 2. 库存口径（关键概念）

本阶段的库存体系只有两个表，职责严格分开：

| 表 | 角色 | 可变性 | 谁能写 |
|---|---|---|---|
| `stock_ledger` | **唯一事实来源** | **只追加（append-only），不修改、不删除** | 单据审核 / 取消审核 / 红冲时写入 |
| `stock_balance` | **派生表**（实时余额） | 由流水**重算**得到，可被清空重建 | 仅重算引擎按原始 SQL 写入，**禁止经 Repository 写入** |

由此得出三条不变式：

1. **数量一律按商品基本单位记账**：录单时可选用「箱 / 包」等辅单位，系统按换算率折算成基本数量后再写流水。
2. **成本按移动加权平均**：`avg_cost = 成本金额 ÷ 现有量`，随流水重算；调拨时成本随货转移（取源仓当前均价），盘点盈亏成本取当前均价。
3. **任何回退都是「再写一条反向流水」**，绝不删除原流水，因此历史可完整追溯、不会出现「删流水导致库存对不上」。

## 3. 库存重算引擎

### 3.1 重算做什么

`recomputeBalance(productId?, warehouseId?)` 由 `stock_ledger` 重新聚合出 `stock_balance`：

- **数量** `qty = Σ qty_in − Σ qty_out`；
- **成本金额** `cost_amount = Σ(入库 amount) − Σ(出库 amount)`；
- **可用量** `avail_qty = qty − locked_qty`（本阶段 `locked_qty = 0`，为 P4/P6 预占预留）；
- **移动加权均价** `avg_cost = cost_amount ÷ qty`（数量为 0 时记 0）。

按 `商品 + 仓库 + 货位` 三个维度分行；商品的 `min_stock / max_stock` 阈值取自主数据。

### 3.2 为什么是「清空 + 重建」而不是逐行加减

重算实现为：**先清空受影响的派生行 → 再按流水聚合重建**。这样：

- **天然幂等**：余额只由流水决定，与写入顺序、重算次数无关；断网期间与联网后的重算结果收敛一致（满足 P3 验收口径）。
- **收敛一致**：`stock_balance` 永远等于「把该维度的全部流水重放一遍」的结果。

### 3.3 增量重算的触发时机

不需要每次全量重算。系统按**本次操作涉及的 (商品, 仓库) 维度**做增量重算：

- P2 采购 / 销售单据：**审核 / 取消审核 / 红冲**后自动重算；
- P3 调拨 / 盘点单据：**审核 / 取消审核 / 红冲**后自动重算。

「实时库存查询」页另提供**「全量重算」**按钮，作为对账兜底：数据异常或担心多端同步后不一致时，点一次即可把全部余额重建。

## 4. 操作说明

### 4.1 推荐使用顺序

1. P1 建好 商品 / 仓库 / 货位 等主数据（预警还需在商品上设 `min_stock` / `max_stock`）。
2. P2 完成采购入库 / 销售出库等业务，库存余额由审核自动写入并重算。
3. P3 用「实时库存查询」核对数量与成本；用「库存流水」追溯每一笔来源。
4. 需要调拨 / 盘点时，用对应页面开单 → 审核生效。

### 4.2 实时库存查询

- **查询条件**：关键字（商品编号 / 名称 / 条码）、仓库；「显示零库存」开关（默认**隐藏数量与金额均为 0 的余额行**）。
- **列**：商品编号、名称、仓库、货位、单位、现有量、可用量、移动加权均价、成本金额、安全库存（下限 / 上限）。
- **标色**：低于下限标红、高于上限标黄（与「库存预警」口径一致）。
- **全量重算**：点「全量重算」重建全部余额，提示「重算完成，更新 N 条余额」。

> 说明：余额按 `商品 + 仓库 + 货位` 分行；同一商品在不同仓库 / 货位各占一行。P3 暂不实现仓库 / 货位间的拆分展示，按流水粒度如实呈现。

### 4.3 库存流水

- **查询条件**：关键字（单据编号 / 商品编号 / 名称）、仓库、业务类型、业务日期区间；「重置」清空条件。
- **业务类型**（与字典一致）：`期初`、`采购入库`、`销售出库`、`部门领用`、`生产入库`、`退货入库`、`退货出库`、`调拨`、`盘点`、`红冲`。
- **列**：业务日期、业务类型、单据编号、商品、仓库、货位、单位、入库、出库、单位成本、金额、冲销标记（红冲流水带「红冲」标签）。
- 流水为**只读**：用于追溯（可按单据编号定位来源单据）与核对冲销；回退入口在单据页，而不是这里。

### 4.4 库存预警

- 按**商品跨仓库汇总**现有量，与商品的 `min_stock / max_stock` 比较：
  - 现有量 < 下限 → 「低于下限」（红）；
  - 现有量 > 上限 → 「高于上限」（黄）。
- 未设置阈值的商品**不告警**（不进入列表）。
- 点「刷新」重新汇总。

### 4.5 库存调拨

- **表头**：调出仓库、调入仓库（必填且**不能相同**）、经手人、业务日期、备注。
- **明细**：搜索或扫码加商品；每行可选**单位**（按换算率折算基本数量）、调出货位、调入货位。
- **保存**：生成 / 更新**草稿（待审核）**，此时不影响库存。
- **审核**（生效）：在一个事务内生成**两条流水** ——
  1. 源仓**出库**（数量 `−`，成本取源仓当前移动加权均价）；
  2. 目标仓**入库**（数量 `+`，成本**同源仓均价**，即成本随货转移）。
  审核前对源仓做**可用量校验**（见 §5.2）。
- **取消审核 / 红冲**：追加反向流水、异地回退，余额随之回退。

### 4.6 库存盘点

- **表头**：盘点仓库（必填）、经手人、业务日期、备注。
- **明细**：每行填**实盘数量**（按基本单位）；保存时系统以**保存那一刻的账面量**作为基准 `book_qty`，差异 `diff_qty = 实盘 − 账面`。
- **审核**（生效）：只为**差异非零**的行生成盈亏流水 ——
  - 盘盈（`diff > 0`）→ 入库流水，成本取当前均价；
  - 盘亏（`diff < 0`）→ 出库流水，成本取当前均价，并做可用量校验。
- **取消审核 / 红冲**：追加反向流水，余额回退。

> 盘点基准是**保存时刻**的账面量。若保存后又发生了新的出入库，盘点单的差异仍以保存时快照为准；如需重算差异，建议取消审核后重新编辑保存。

## 5. 单据状态机与校验

### 5.1 状态机（与 P2 一致）

| 状态值 | 含义 | 可执行操作 |
|---|---|---|
| 0 | 待审核（草稿） | 编辑、审核 |
| 1 | 已审核（生效） | 查看 / 取消审核 |
| 9 | 已红冲 | 仅查看，不可再操作 |

只有 `status = 1`（已审核）才写流水、才影响库存。

### 5.2 审核前置校验

- **调拨**：调出 / 调入仓库必填且不同；源仓**可用量**校验（`allow_negative_stock = 0` 时），不足则一次性列出全部不足项，格式 `库存不足：商品「X」在仓库「Y」可用 A，需 B；…`。
- **盘点**：盘点仓库必填；**盘亏行**做可用量校验（不足同样拒绝审核）。
- 明细为空时禁止审核。

### 5.3 取消审核 / 红冲的前置校验

命中以下任一情况**不允许**操作：

1. 单据**已红冲**（状态 9）→ 提示「单据已红冲，不能再次操作」；
2. 单据**已被红冲单引用**（存在 `reversal_of` 指向它）→ 提示「该单据已被红冲单引用，请先处理红冲单」；
3. 取消审核时，若自身某条流水**已被冲销**，也会拒绝并提示「该单据的库存流水已被冲销」。

### 5.4 取消审核 vs 红冲

| 操作 | 效果 | 适用场景 |
|---|---|---|
| 取消审核 | 为自身流水写反向流水，状态回 `0`，可继续编辑后重新审核 | 录错、要改内容（不留反向单据） |
| 红冲 | 生成一张**反向已审核单据 R**（`reversal_of` 指向原单），原单置 `9` | 单据已对外发生，要留痕作废 |

调拨红冲时，R 会**交换调出 / 调入仓库与货位**再生成反向流水；盘点红冲按原差异反向记账。

## 6. 数据出错如何回滚

- **口径**：`stock_ledger` append-only，回退一律体现为**新增反向流水**；`stock_balance` 由重算收敛，因此不会出现余额与流水不一致。
- **常见处置**：

| 误操作 | 处置方式 | 结果 |
|---|---|---|
| 草稿单填错 | 「编辑」修改后保存 | 无库存影响 |
| 已审核调拨 / 盘点填错 | 「取消审核」→ 改 → 再审核；或「红冲」 | 库存先回退再重算 / 留反向凭证 |
| 余额显示不对 | 「实时库存查询 → 全量重算」 | 由流水重建，恢复一致 |
| 多端数据疑似不一致 | 全量重算 | 以流水为准收敛 |

## 7. 与后续阶段的衔接

- **P4 财务**：`avail_qty / locked_qty` 已预留，供预占 / 核销联动的可用量口径使用。
- **P5 报表**：库存流水与余额已可查询，报表将据此出「库存账」「进销存」等。
- **P6 小程序**：查询库存 / 扫码查库存直接读 `stock_balance`（同步后一致）。
- **P7 同步**：`stock_balance` 为派生表、不可直接同步；同步 `stock_ledger` 等事实数据后，各端**重算收敛**到同一结果。

## 8. 常见问题

**Q1：为什么调拨后源仓与目标仓的金额相同？**
调拨**不产生盈亏**，成本随货转移：源仓按当前均价出库，目标仓按**同一均价**入库，因此两边金额一致，只是仓库位置变了。

**Q2：盘点盘盈为什么也按「当前均价」而不是「重新计价」？**
盘盈入库沿用该商品 / 仓库的当前移动加权均价，避免因盘点动作扰动整体成本；盘亏出库同理。真正的成本变动应通过采购入库等业务体现。

**Q3：为什么改完盘点单，差异和之前不一样了？**
盘点的基准 `book_qty` 是**保存那一刻**的账面量快照。保存后若又发生出入库，账面量变了，但本单差异仍按旧快照。要按新基准盘点，请**取消审核后重新编辑保存**。

**Q4：「实时库存查询」看不到某商品，是不是丢了？**
默认隐藏「数量与金额均为 0」的行。打开筛选区的**「显示零库存」**开关即可看到零库存商品。

**Q5：余额与流水对不上怎么办？**
先点「实时库存查询 → **全量重算**」。余额是流水的派生结果，重算后必然与流水一致；若重算后仍异常，请核对是否有异常的直接写库操作（正常业务不应绕过单据写 `stock_ledger`）。

**Q6：调拨审核提示「库存不足」怎么办？**
源仓可用量不足。先从其他仓库调拨补货或采购入库，或在「系统 → 设置」打开 `allow_negative_stock`（默认关闭，不建议）。

**Q7：调拨时「调出仓库」和「调入仓库」能相同吗？**
不能，系统会以「调出仓库与调入仓库不能相同」拒绝。仓库内部的位置变动请用货位区分，不要用同仓调拨单。

**Q8：红冲后的调拨 / 盘点单还能改吗？**
不能。原单状态为 `9`（已红冲），仅可查看；如需修正，请新开单据。
