## 2. 单据状态机

| 状态值 | 含义 | 可执行操作 |
|---|---|---|
| 0 | 待审核（草稿） | 编辑、审核、删除草稿 |
| 1 | 已审核（生效） | 查看、取消审核、红冲；订单还可转单 |
| 9 | 已红冲 | 仅查看，不可再操作 |

**只有 `status = 1`（已审核）的单据才生效**：才会写库存流水、生成应收/应付。

> 关键约束：库存流水表 `stock_ledger` 是**绝对只追加（append-only）**的，任何「回退」都是**再写一条反向流水**，而不是删除原流水。单据本身的可变性由上面的状态机约束。

## 3. 操作说明

### 3.1 推荐使用顺序

1. 先在 P1「基础资料」建好 商品 / 供应商 / 客户 / 仓库 / 部门 / 经手人（用户）。
2. 采购侧：**采购订单**（可选）→ 审核 →「转入库」生成**采购入库单** → 补货位 → 审核 → 库存增加 + 生成应付。
3. 销售侧：**销售订单**（可选）→ 审核 →「转出库」生成**销售出库单** → 审核 → 库存减少 + 生成应收。
4. 领用 / 生产 / 退货：直接在对应页面新增单据 → 审核。

> 订单不是必须的：采购入库单、销售出库单都可以**直接新增**（无需先开订单）。

### 3.2 列表页

- **查询**：按 关键字（单据编号 / 备注）、状态（待审核 / 已审核 / 已红冲）、业务日期区间 筛选；「重置」清空条件。
- **列**：单据编号、类型、往来单位（供应商/客户）、仓库、业务日期、金额、状态标签、经手人、备注。
- **行内操作**：按状态动态显示 —— 待审核显示「编辑 / 审核」；已审核显示「查看 / 取消审核 / 红冲」（订单另有「转入库 / 转出库」）。

### 3.3 单据编辑弹窗

- **表头**：往来单位、仓库、经手人、业务日期、备注；不同类型额外显示 领用部门 / 领用人 / 用途（仅部门领用）。
- **明细**：可通过「搜索并添加商品」或「扫码 / 输入条码 → 扫码添加」加行；每行可选**单位**，系统按单位换算率自动折算**基本数量**（库存一律按基本单位记账）。
- **单价**：选定商品后按进价（采购侧）或售价（销售侧）预填，可改。
- **货位**：采购入库单 / 销售出库单的明细可指定货位（随仓库联动）。
- **金额/合计**：金额 = 数量 × 单价（保留 2 位）；底部显示合计。
- 保存即生成/更新**草稿（待审核）**，此时**不影响库存、不生成往来单**。
- 单据编号：新建时按编号规则自动生成（详见 §6 Q1）。
- **已审核单据为只读**：弹窗会自动进入「查看」模式，需先「取消审核」才能改。

### 3.4 审核（生效）

审核在**一个事务内**完成：写库存流水、必要时生成应收/应付、更新单据状态。各类型审核效果如下表：

| 页面 / 单据类型 | 单据类型值 | 库存方向 | 成本取值 | 往来单 |
|---|---|---|---|---|
| 采购订单 / 销售订单 | — | **不动库存** | — | 不生成 |
| 采购入库单 | 采购 | 入库（+） | **按明细单价** | 生成**应付**（+金额） |
| 采购入库单 | 部门领用 | **出库（−）** | 移动加权平均 | 无 |
| 采购入库单 | 生产入库 | 入库（+） | 按明细单价 | 无 |
| 采购入库单 | 退货入库 | **出库（−）**退回供应商 | 移动加权平均 | 生成**应付**（−金额，冲减） |
| 销售出库单 | 销售 | 出库（−） | 移动加权平均（快照写入明细 `cost_price/cost_amount`） | 生成**应收**（+金额） |
| 销售出库单 | 退货出库 | **入库（+）**客户退回 | 移动加权平均 | 生成**应收**（−金额，冲减） |

> 「部门领用」「退货入库」虽然录入在**入库单**页面，但业务上是**出库**（货离开仓库），审核会对库存做减项；反之「退货出库」是入库。方向以业务实质为准，不认页面名称。

**审核前置校验**

1. **负库存**：当系统设置 `allow_negative_stock = 0`（默认禁止）时，出库方向会校验可用量；不足则**审批不通过**，一次性列出所有不足项，格式为：`库存不足：商品「X」在仓库「Y」可用 A，需 B；…`。
2. **往来单位必填**：采购入库（采购）/ 销售出库（销售）生成往来单时，缺供应商/客户会拒绝审核。

### 3.5 转单（订单 → 出入库单）

- 在**已审核**的采购订单 / 销售订单行上点「转入库 / 转出库」，系统生成一张**草稿**的采购入库单 / 销售出库单，复制订单的表头与明细（货位留空待补）。
- 转单条件：订单必须**已审核**；且该订单**尚未生成**过对应出入库单（重复点击会提示「该订单已生成对应的出入库单」）。
- 生成的出入库单仍需**再次审核**才会影响库存与账。

### 3.6 取消审核

- 作用：把已审核单据**回退到待审核**，期间：
  1. 为自身每条库存流水写一条**反向流水**（方向相反、成本不变）；
  2. **作废**（软删除）该单据生成的应收/应付；
  3. 单据状态回 `0`，清除审核人/审核时间。
- 回到待审核后即可继续修改，改完再审核。
- **前置校验**：命中以下任一情况**不允许**取消审核 ——
  1. 单据**已红冲**（状态 9）；
  2. 其应收/应付**已发生收付款核销**（提示「请先反核销」）；
  3. **已被下游单据引用**（订单已转出库、或已被红冲生成过反向单）。

### 3.7 红冲

- 作用：生成一张**反向已审核单据 R**（`reversal_of` 指向原单），并把**原单置为已红冲（9）**。
- 效果：
  1. R 复制原单表头 + 明细；
  2. 为原单每条**未被冲销**的库存流水，在 R 名下写一条方向相反的流水（成本取原流水成本）；
  3. 生成**金额相反**的应收/应付（挂在 R 上）。
- 红冲后的**原单不可再操作**，需查看/对比时看 R 即可。
- **前置校验**：同「取消审核」的三条规则（已红冲 / 已核销 / 已被下游引用）。

> 取消审核 vs 红冲怎么选？
> - **录错了、要改内容** → 用「取消审核」，回待审核直接改，改完再审核（不留反向单据，账面更干净）。
> - **单据已经对外发生、要留痕作废** → 用「红冲」，保留一张反向单据作为凭证，原单归档为已红冲。

## 4. 数据出错如何回滚

### 4.1 口径：append-only + 反向流水

- 库存唯一事实来源是 `stock_ledger`，**只增不改不删**。所有回退都体现为**新增反向流水**，因此历史可完整追溯。
- 「取消审核」「红冲」都会写反向流水；因此**不会**出现「删掉一条流水导致库存对不上」的情况。

### 4.2 各类误操作的处置

| 误操作 | 处置方式 | 结果 |
|---|---|---|
| 草稿单填错 | 直接「编辑」修改后保存 | 无库存/账影响 |
| 已审核单填错（未对外） | 「取消审核」→ 回到待审核 → 改 → 再审核 | 库存与往来单先回退再重算 |
| 已审核单填错（已对外） | 「红冲」 | 留反向凭证，原单归档为已红冲 |
| 多开了一张单据 | 同上：能改就「取消审核」，已对外就「红冲」 | — |
| 已核销（已收付款）的单据想回退 | **先反核销**收付款，再「取消审核」或「红冲」 | 系统会以「请先反核销」阻止越级操作 |

### 4.3 常见报错与含义

| 报错 | 含义 / 处理 |
|---|---|
| 库存不足：… | 目标仓库可用量不够。先入库补货，或在「设置」打开 `allow_negative_stock`（不建议）。 |
| 单据已审核，请先「取消审核」后再修改 | 已审核内容不可改；先取消审核。 |
| 该单据的应收/应付已发生收付款核销，请先反核销 | 需先撤销对应收付款核销（P4 财务模块提供）。 |
| 该单据已被下游单据引用，请先处理下游单据 | 订单已转出入库单，或已被红冲；先处理下游/反向单。 |
| 单据已红冲，不能再次操作 | 状态 9 的原单不可再取消审核/红冲。 |
| 该订单已生成对应的出入库单 | 转单只能做一次；多余的一单请手工新增。 |
| 采购入库缺少供应商 / 销售出库缺少客户 | 生成往来单必须有往来单位，补齐后再审核。 |

### 4.4 备份 / 恢复

- P2 仍**未提供界面化备份**（计划随 P3 接入）。批量开单前建议手动备份数据库文件：
  - 退出桌面端 → 复制用户数据目录下的 `inventory.db`（连同 `-wal`/`-shm`）；
  - 出错时：退出程序 → 用备份覆盖 → 重启。
- 注意：本阶段**同步尚未启用（P7）**，多台电脑数据互相独立，**请勿在多台机器上同时录入同一批单据**。

## 6. 常见问题

**Q1：新建单据的编号是怎么来的？没配规则也能开单吗？**
能。首次开某种单据时，系统会**惰性创建**对应的编号规则并立即取号，默认前缀与位数如下：

| 单据 | 编号规则适用对象 | 默认前缀 | 位数 |
|---|---|---|---|
| 采购订单 | `doc_no.purchase_order` | `PO` | 5 |
| 采购入库单 | `doc_no.purchase_inbound` | `RK` | 5 |
| 销售订单 | `doc_no.sales_order` | `SO` | 5 |
| 销售出库单 | `doc_no.sales_outbound` | `CK` | 5 |

到「基础资料 → 编码规则」即可看到这些规则，并可改前缀/位数/当前序号（只保证不重复，不保证连续）。

**Q2：为什么「部门领用」在采购菜单下却让库存减少？**
「采购（入库） / 销售（出库）」是**菜单归类**，不决定库存方向。部门领用、退货入库的业务实质是**出库**（货离开仓库），所以审核时做库存减项。

**Q3：审核后库存流水在哪看？**
P2 阶段请到「库存」菜单查看（该页面在 P3 才完全实现）；也可从数据库 `stock_ledger` 直接核对。P3 会提供「库存流水」只读列表与按单据追溯。

**Q4：审核后又发现数量写错，怎么改最快？**
若尚未收付款、也未转下游单：点「取消审核」→ 回待审核 → 编辑改正 → 重新审核。这样账面只留一组反向/正向流水，最干净。

**Q5：为什么「取消审核」按钮点了报错？**
多半命中三条前置校验之一：单据已红冲 / 已发生收付款核销 / 已被下游引用。按 §4.3 的提示先处理上游。

**Q6：红冲后原单还能编辑吗？**
不能。原单状态为 9（已红冲），仅可查看；修正内容请通过新开的单据进行。

**Q7：一张采购订单能转几次入库？**
**一次**。转出的入库单为草稿，可继续编辑；如需分批入库，请在此基础上手工再新增入库单。

**Q8：允许负库存怎么开？**
「系统 → 设置」把 `allow_negative_stock` 改为 1（`sys_config`）。开启后出库审核不再校验可用量，可出成负数。**默认关闭**，建议保持关闭。

**Q9：纸质/外部的单价与系统不一致怎么办？**
明细单价可手工修改（不影响换算率折算）。系统按明细单价记金额；出库成本另按**移动加权平均**计算并快照到明细的 `cost_price/cost_amount`（供 P5 毛利表使用）。
