## 2. 云函数 `mp` 与动作

所有能力收敛在**单个云函数 `mp`** 内，按入参 `action` 分发（`cloudfunctions/mp/handler.js`）。这样避免了 CloudBase 部署时跨目录公共代码依赖的问题。

| action | 组装来源 | 入参 | 返回（`data`） |
|---|---|---|---|---|
| `login` | `login.js` | — | `{ user: { id, name, account, roleId, roleName } }` |
| `query` | `stock.js` | `keyword, page, pageSize` | `{ items:[{productId,code,name,spec,barcode,unit,warehouseName,qty,availQty,avgCost,salePrice}], total }` |
| `lookup` | `stock.js` | `barcode` | `{ product: {…} \| null }`（主条码优先，其次商品条码表） |
| `detail` | `stock.js` | `productId` | `{ product:{…}, balances:[{warehouseId,warehouseName,qty,availQty}] }` |
| `alerts` | `stock.js` | `limit` | `{ items:[{productId,name,code,qty,minStock}], total }`（低于预警线，缺口升序） |
| `meta` | `order.js` | — | `{ customers:[{id,name}], warehouses:[{id,name}] }` |
| `create` | `order.js` | `customerId, warehouseId, bizDate, remark, items[]` | `{ docId, docNo, totalAmount }` |
| `mine` | `order.js` | `page, pageSize` | `{ items:[{docId,docNo,customerName,amount,status,bizDate,itemCount}], total }` |
| `arMine` | `ar.js` | `page, pageSize` | `{ items:[{customerId,customerName,amount,receivedAmount,outstanding,dueDate}], total }` |

统一返回格式：成功 `{ ok:true, data }`；失败 `{ ok:false, code, message, detail }`。错误码：`VALIDATION` / `NOT_BOUND` / `NO_PERMISSION` / `CLOUD`。

> **全部动作（含只读）都先经过 `resolveUser` 校验**，因此「小程序可见角色范围」对每个入口都生效，不只是登录。

**开单落库口径**：`create` 写入 `sales_outbound`（`status = 0 待审核`、`outbound_type = '销售'`）与 `sales_outbound_item`，并带齐桌面端 §4.2 同步字段（`created_by / created_at / origin_device='mp' / sync_state` 等），供 P7 拉取。单据需在**桌面端审核**后才写库存流水、才生效——与设计文档 §5.0 一致。

**幂等**：离线补传时客户端在 payload 里带 `docId`；若该 `docId` 已落库，`create` 直接返回既有单号，不重复写单。

## 3. 云数据库集合

小程序端读写的云集合（字段与桌面端 schema **对齐**，便于 P7 同步）：

| 集合 | 用途 | 由谁维护 |
|---|---|---|
| `mp_binding` | `{ openid, user_id }` 微信 openid ↔ 系统用户绑定 | 管理员（桌面端/控制台） |
| `mp_config` | `{ key:'mp_visible_roles', value:[roleId…] }` 可见角色范围 | 管理员 |
| `app_user` / `role` | 用户与角色（登录校验用） | P1 主数据同步 |
| `product` / `product_barcode` / `unit` / `warehouse` / `customer` | 商品、条码、单位、仓库、客户 | P1 主数据同步 |
| `stock_balance` | 商品分仓实时库存（`qty / avail_qty / cost_amount`） | P3 派生同步 |
| `sales_outbound` / `sales_outbound_item` | 小程序提交的销售出库单（待审核） | 云函数 `create` |
| `ar_bill` | 应收单据（未收款来源） | P4 同步 |

**初始化要点**：在微信开发者工具「云开发 → 数据库」手工创建上述集合。首次使用至少要有 `mp_binding` 与 `app_user` 各一条记录，才能登录成功。

`mp_config` 若**不存在** `mp_visible_roles` 文档，或 `value` 为**空数组**，表示**不限制**（所有角色可用）；一旦填入角色 id 列表，仅列表内角色的用户可登录/调用。

## 4. 权限与账号绑定

1. **绑定**：管理员在 `mp_binding` 里为某个微信用户的 openid 绑定 `app_user.id`。绑定前，小程序登录会返回 `NOT_BOUND`，提示「请先在『我的』页完成绑定」。
2. **可见角色范围**：`mp_config.mp_visible_roles` 配置允许使用小程序的角色 id 列表。角色不在范围内 → `NO_PERMISSION`（提示联系管理员开通）。**该范围对登录与所有业务动作均生效**。
3. **切换账号**：Tab4「我的」里的「切换账号」会清空本地登录态与离线队列并重新静默登录（用于换微信/换绑场景）。

> 小程序端不做自动注册：未绑定就是未绑定，避免误把任意微信用户当成系统用户。

## 5. 离线队列（离线优先）

| 文件 | 职责 |
|---|---|
| `lib/offline-queue.js` | **纯逻辑**核心（无 `wx` 依赖）：去重、重试编排、并发互斥。可在 `node:test` 下直接单测 |
| `lib/mp-queue.js` | 绑定 `wx` 本地存储的单例 + 网络恢复自动补传 |
| `api/index.js` | 写接口遇 `NETWORK` 错误自动入队；只读接口走带重试的直连 |

关键行为：

- **幂等键 `type:docId`**：同一单据只保留最新 payload，「离线改单 → 反复入队」不会产生重复提交；云端再靠 `create` 的 `docId` 幂等兜底。
- **网络错误不消耗重试额度**：队列区分 `NETWORK` 与其他业务失败，前者不递增 `retries` 并立即中断投递，避免离线时把额度耗尽。
- **自动补传**：注册 `wx.onNetworkStatusChange`，网络恢复即自动 `flush`；用户也可在「工作台 / 我的」点「立即同步」。
- **并发互斥**：`flushing` 标志保证「网络恢复」与「手动同步」不会并发投递同一批。
- 队列摘要（待发 / 重试 / 阻塞）展示在工作台与「我的」页。

配置在 `config/index.js` 的 `QUEUE`：`max:200 / batch:20 / retryDelayMs:3000 / maxRetry:5`（线性退避）。

## 6. 部署与联调步骤

1. **填配置**（全项目仅两处）：
   - `config/index.js` 的 `ENV.envId`：填云开发环境 ID；留空则用默认环境。
   - `project.config.json` 的 `appid`：替换 `touristappid` 为你的小程序 AppID。
2. 用**微信开发者工具**打开 `apps/miniprogram` 目录。
3. 工具内按提示**构建 npm**（`tdesign-miniprogram` 需要生成 `miniprogram_npm`）。本工程**不进 pnpm workspace**，用 `npm install` 安装依赖（pnpm 软链结构无法被「构建 npm」解析）。
4. 云端：右键 `cloudfunctions/mp` → **上传并部署（云端安装依赖）**。首次部署后，在「云开发 → 数据库」创建 §3 的集合与初始化数据。
5. 真机调云函数需在**小程序后台 → 开发设置 → 服务器域名**里放行云开发域名（云调用默认已放行，一般无需额外配置）。

## 9. 常见问题

**Q：登录一直返回 `NOT_BOUND`？**
`mp_binding` 里没有当前微信 openid 的绑定记录。请管理员用该用户微信的 openid 在 `mp_binding` 中绑定 `app_user.id`。

**Q：提示「当前角色暂无小程序使用权限」？**
该用户角色不在 `mp_config.mp_visible_roles` 的 `value` 列表里。要么把该角色 id 加入列表，要么清空列表（空数组 = 不限制）。

**Q：离线开单后单据会丢吗？**
不会。提交失败（网络类）会进本地离线队列，网络恢复自动补传或在「我的」点「立即同步」。云端 `create` 按 `docId` 幂等，重复补传也只落一张单。

**Q：「我的」页显示「阻塞 N」是什么意思？**
队列里这些操作重试次数已达 `maxRetry`（默认 5），多为**业务性失败**（如客户/仓库已被停用）。请检查单据内容后在云端处理；网络问题不会消耗重试额度，因此不会因断网被误判为阻塞。

**Q：开单后桌面端看不到 / 库存没变？**
小程序提交的是**待审核**单据（`status = 0`）。需在桌面端「销售出库」里**审核**后才写库存流水、才生效（设计文档 §5.0）。这是刻意设计，避免移动端越权直接改库存。

**Q：查库存的数据从哪来？**
来自云端 `product` + `stock_balance` 集合（由桌面端 P1/P3 同步而来）。若列表为空，先确认主数据与库存已同步到云。
